# 棱镜残像：GPU 合成

素材模板现在使用 WebGL2 合成原有 score 的画面，保留 1080×1080、30 fps、
素材选择、配色、阶段边界、卡点、负片时长和效果频率。体素干扰模板保持原样。

`material-gpu.mjs` 实现现有布局所需的变换、裁切、路径遮罩、纹理绘制和边线。
素材解码成 ImageBitmap，纹理上传时避免额外翻转、预乘转换和重复分配。
万花筒和四向镜像分别批量绘制；拖影复用最多八张历史布局纹理。
景色亮度、占用比例、负片纹理区域选择由 GPU 计算，不再把整幅像素读回 CPU。
GPU 直接输出到编码 Canvas，WebCodecs 继续优先使用硬件编码。

图集最多保留十张解码图片，GPU 图像纹理缓存最多十六项，中间纹理按尺寸复用。
解码结果在淘汰/销毁时 close。预览重建使用新的 Canvas，避免 2D/WebGL
上下文不能互换的问题。素材预处理缓存与渲染器版本分开，之后仅修改 shader
不会重新生成图集；旧缓存第一次切换到新缓存身份仍可能需要一次准备。

硬件 WebGL、浮点渲染目标或纹理尺寸能力不足时，沿用既有 Canvas 路径。
可通过 `BEATSCOPE_MV_COMPOSITE=0` 比较旧合成路径，仍保留此前的 GPU 遮罩。
`BEATSCOPE_MV_GPU=0` 关闭两种 GPU 路径。正常使用不需要设置。

本机 RTX 5060 Laptop 的同一 8 秒片段（原曲 12–20 秒），两路均使用硬件编码：

| 指标 | 旧合成 | 新合成 |
| --- | ---: | ---: |
| 正式渲染阶段耗时 | 4.038 秒 | 3.085 秒 |
| 浏览器各进程累计 CPU 时间 | 5.884 CPU 秒 | 4.426 CPU 秒 |
| 含启动和检查的总耗时 | 6.733 秒 | 6.231 秒 |

渲染阶段耗时减少约 24%，累计浏览器 CPU 时间减少约 25%。这不是任务管理器
占用百分比，也不包含所有宿主进程或首次素材预处理；尚未在低配置电脑实测。
开发中首次直接迁移曾更慢，经过纹理上传和批量绘制修正后才启用当前实现。

51 个抽样点覆盖各布局、转场、负片和景色效果；最大平均 RGB 通道误差
0.8505/255，单点通道差超过 12 的比例最大 0.2713%。边缘抗锯齿、纹理采样
和遮罩量化存在细微差异，不声称逐像素相同。倒序跳转与重访输出完全一致。全屏画面用单个覆盖三角形绘制，避免多重采样对角接缝随重访发生差异。强制禁用 WebGL 的回退检查保持原 Canvas 输出一致。
两路短片均验证为 1080×1080、30 fps、240 帧、8 秒并带音频。

使用现有项目依赖重跑有界对照：

```powershell
node tests/browser/gpu-render-check.mjs
node tests/browser/gpu-encode-sample.mjs
```

CPU 仍负责图片解码、score 查询、路径顶点和文字小纹理准备、音频及浏览器调度。
GPU 上下文运行中丢失会明确报错，初始化阶段能力不足则自动选择旧路径。
