# Compose music and picture together

The package carries facts, editable passage/cue timing and generic choreography,
no style or job score. Resolve edit-plan.json first. Preserve its stage boundaries
and manual response times in the executable score; facts remain available for
other motion and timing queries. A deleted response is not a deleted music fact.

## One reference pass
References and supplied assets are optional, not required intake fields.
Use accepted direction and source authorization when available. Without a
reference, design from the brief and musical timing. Without assets, choose
procedural visuals or online sources within authorization. Do not invent online
selection permission. If direction and source authorization are both unclear,
ask one combined question about direction and autonomous sourcing; otherwise
ask only for blocking inputs. Never require technical parameters or project versions.
Record your design choices as authored choices, not reference observations.

When references exist, inspect representative continuous passages and native consecutive frames where
motion is dense. Slow accelerated references without guessing original speed;
check the slowed output covers the source interval. Retain focal path, scale,
layer speed differences, preparation/arrival and what survives. Cache these
observations in score notes. Inspect relevant sources; reuse known asset choices
and retain usage conditions.
Stills supply image detail, not filmed travel or recovered physical geometry.

## One compact executable score
Use reusable shots, event groups, stages and shared tracks from SKILL.md. The score is the working
plan; a separate long directing report is unnecessary.

Each stage identifies its focus and a change in relationships: what the viewer
learns, enters, loses or sees return differently. Continuity can use subject,
composition, direction, shape, material, theme or deliberate contrast. There is
no mandatory enter/explode/reassemble sequence. Develop long stages internally.

Choose visual rhythm from music BEFORE designing long motion. For each passage,
read ordinary beats, onset spacing, repeated attacks, gaps and stage changes.
Choose hold, switch or alternate, and a visual reason for the passage. Build
related shot setups to realize it; then author local motion and layer handoffs.
These are short stage.rhythm entries in the executable score, not a new report.
Without references still make these choices; slow drift is not a neutral default.

An alternate passage can revisit a subject from different scales, directions,
material states or spatial relationships. Establish a visual connection across
cuts and change the relationship when the music develops. A hold can be vigorous
travel, occlusion or transformation toward a destination. A stage is a musical
chapter, not a shot duration: it may contain many visits and internal passages.
Do not reuse one alternating pattern throughout the song. One event can cut,
complete a camera arrival and pass a foreground layer together; several events
can form one pattern. There is no required one-event/one-action assignment.

Keep a focal hierarchy and source/route/destination for motion. Supporting layers
provide occlusion, depth, reveal or carryover. Band activity may modify a chosen
track, but scalar rotation, brightness and scale pulses alone do not implement a
declared shot sequence. The adapter must use view.id/setup, not just values.

Within representative shots, retain what reveals, crosses, occludes, changes
framing and survives. Matching cut counts alone does not reproduce their pace.
Use those observations with the actual music facts; there is no universal quota
of internal changes and no required one-event/one-action assignment.

Reuse native framing and setters. Optional picture-tools.js helpers can fit
actual targets or bind a score; read only the needed API in picture-tools.md.
They add no separate analysis or check. Actual pixels still determine whether
the declared view shows readable detail and convincing depth.

Use explicit preparation and destination keys. Short arrivals, holds, cuts and
anticipation are available; phrase-length easing is not a default. Changes persist
unless authored to reset. Use shake selectively. Ranked onsets and structure
labels are candidates, not functions or cut instructions. Activity is not
loudness; RMS is amplitude, not perceived loudness. Keep listening claims honest.

Cut within an advancing world. Shared camera travel, depth handoff and retained
changes use global progress tracks; viewpoints may alternate while the process
continues. MV local clocks continue offscreen by default. Explicit visible or
restart clocks are choices for pause/replay, not substitutes for shared progress.
A short impact can finish without freezing the scene. Follow it with movement
toward a destination or an intentional rest. Do not add unrelated drift just to
make pixels change. During the existing preview check, inspect the held interval
AFTER the impact and a returning shot; checking only cut/impact frames misses stalls.

Cuts are valid on ordinary beats, dense onset runs and accents. Related shots can
alternate and return; a new shot at every event is unnecessary. Read the actual
spacing, repeated pattern, gaps and phrase changes before choosing a combination.
Group numerical onsets only as inspection evidence. Return clocks can continue,
pause or replay the shot. At a new stage, author an entry or explicit carry and
change its composition/relationship; do not perpetuate one cut pattern all song.
The Agent authors this score; never ask the user to become the editor.

## Bounded production check
For a scoped revision, reuse accepted direction, reference observations, assets,
score and renderer. Inspect an uncached reference passage only when the requested
change depends on it. Check the changed interval and necessary seam; retain
unaffected verification. Do not rebuild an approved piece as a new production.
For a new piece, default to one representative 24–30fps preview covering ordinary beats, an accent
and a stage handoff. When references exist, compare paired moving reference/output
with audio once; otherwise review against the declared direction and musical timing;
check focus/readability, arrival/consequence and the next visual condition.
An unreadable promised focal title remains a mismatch; renaming it does not
fulfill the promise. Program checks timing consistency, not taste.

Cache the decision. Revisit only affected intervals after concrete failure.
Whole-song animatics, multiple reports, exhaustive frames and parallel trials
are not default gates. Expand an adequate preview once. Repeated failures need
an approach change or honest limitation, not an unbounded tweak/render loop.
Follow the user's stricter stop/render instructions.

Use the same renderer and absolute clock. Reset base state; apply compiled values
through one adapter, update/decode media and render once. Every seek path uses
excerptStart + localTime. Source-time keys need actual media seeking/preprocessing.
Wait for fonts/images/video decode; preserve revision-bound evidence. Check final
encoding and relevant seams/tail. Deliver media, source and rerender command with
concise matched, mismatch and unverified findings.
